Realtime, embedded.

This page is served by an ordinary web server (Go, Node, .NET or Python). That same server is also answering Ably SDK traffic — so the messages below are flowing through a realtime endpoint your app hosts itself. No separate server, no extra infrastructure to install.

Dev only. The API key app.key:secret is visible in this page's source. That's fine for a throwaway local dev key, but in production you never ship a key to the browser: mint short-lived tokens server-side and use ably-js authUrl. The embedded endpoint issues tokens at POST /keys/{keyName}/requestToken.

    The entire client wiring

    // unmodified ably-js, pointed at this page's own origin
const ably = new Ably.Realtime({
  key: 'app.key:secret',   // dev key for the embedded server
  restHost: location.hostname,
  realtimeHost: location.hostname,
  port: Number(location.port),
  tls: location.protocol === 'https:',
});
const channel = ably.channels.get('demo:feed');
channel.subscribe('msg', (m) => render(m.data));
channel.publish('msg', { text, who });

    That's it. The host app just reverse-proxies (or in Go, in-process mounts) Ably on its own port. In production you'd swap the dev key for token auth (an authUrl), and ship the server binary as a normal package dependency.

    No dependency to install

    The realtime endpoint ships inside your app — a package dependency, not a service to provision.

    No separate server to run

    It's the same process (or a supervised child) on the same port. One thing to deploy.

    Just an endpoint, attached

    Point any unmodified Ably SDK at host + port. Pub/sub, history, presence, resume — all there.
